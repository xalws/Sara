0. Cómo leer este manual

Cada proceso tiene una ficha con sus archivos, su punto de entrada y su resultado, seguida de los pasos en el orden en que ocurren en el código. Los nombres entre así son funciones, clases o variables reales del proyecto (todos en español y sin acentos). Las rutas parten de app/src/main/.

1. Arranque y menú principal

ArchivosMainActivity.kt, res/layout/vista_principal.xml EntradaAndroid abre MainActivity (declarada como LAUNCHER en el manifiesto). ResultadoSe ve el menú con Inicio activo y el contenido de vista_inicio.xml (o Aprendizaje, si se llegó con el botón "Regresar").
  1. onCreate(estadoGuardado) aplica setContentView(R.layout.vista_principal).
  2. Llama a findViewById<View>(R.id.raizPrincipal).respetarBarrasDelSistema() para que el menú no quede debajo de la hora (proceso 3, "Barras del sistema").
  3. Con findViewById se obtienen contenedorPrincipal (FrameLayout) y los tres ImageButton: btnInicio, btnAprendizaje y btnGraficar.
  4. Si el Intent trae seccion = aprendizaje (pideAprendizaje(intent)), muestra Aprendizaje con mostrarAprendizaje(); si no, llama a cambiarPantalla(R.layout.vista_inicio) y a marcarBotonActivo(btnInicio).
  5. Cada botón del menú repite el mismo par de llamadas con su diseño correspondiente (Aprendizaje usa mostrarAprendizaje()).

onNewIntent(intencion)

Cuando una pantalla de tema usa "Regresar", MainActivity ya existe en la pila. Gracias a FLAG_ACTIVITY_SINGLE_TOP no se crea otra: Android llama a onNewIntent, que guarda el Intent con setIntent y, si pide Aprendizaje, llama a mostrarAprendizaje(). Esta vuelve a inflar vista_aprendizaje y marca su botón del menú en amarillo.

cambiarPantalla(idDiseno)

  1. Si había una graficadora abierta, llama a grafica?.destruir() para liberar el WebView, la voz y el audio.
  2. Vacía el contenedor con removeAllViews().
  3. Infla el diseño nuevo con LayoutInflater.from(this).inflate(idDiseno, contenedorPrincipal, false) y lo agrega.
  4. Si es vista_grafica, crea ControladorGrafica(this, nuevaPantalla).
  5. Si es vista_aprendizaje, llama a configurarBotonesAprendizaje(nuevaPantalla).

marcarBotonActivo(boton) pone el fondo btn_morado a los tres botones y btn_amarillo al activo.

2. Botones de Aprendizaje e Intents

ArchivosMainActivity.kt (configurarBotonesAprendizaje), vista_aprendizaje.xml EntradaLa persona toca un botón de tema. ResultadoSe abre la Activity del tema.
  1. Como vista_aprendizaje se infla dentro del contenedor, sus botones se buscan sobre esa vista: pantalla.findViewById<Button>(R.id.btnTemaLineal), etc. (11 botones).
  2. Cada botón recibe un setOnClickListener que ejecuta startActivity(Intent(this, FuncionLinealActivity::class.java)).
  3. El diseño agrupa los botones bajo títulos de tema (accessibilityHeading="true"), para que TalkBack pueda saltar de un tema a otro.
btnTemaLineal.setOnClickListener {
    startActivity(Intent(this, FuncionLinealActivity::class.java))
}

3. Pantallas de tema con ViewBinding

ArchivosFuncion*Activity.kt, FuncionesActivity.kt, PlanoCartesiano*Activity.kt; build.gradle.kts (viewBinding = true) EntradaEl Intent del proceso 2. ResultadoLa pantalla del tema con su plano sonoro configurado.
  1. Gradle genera una clase por diseño: vista_funcion_lineal.xml → VistaFuncionLinealBinding. Cada id se vuelve una propiedad (planoSonoro, btnSonidoLineal, btnReferencias).
  2. En onCreate: enlace = VistaFuncionLinealBinding.inflate(layoutInflater) y setContentView(enlace.root).
  3. enlace.root.respetarBarrasDelSistema() ajusta los márgenes a las barras del sistema.
  4. enlace.btnRegresar.setOnClickListener { regresarAAprendizaje() } conecta el botón "Regresar".
  5. Se configura el plano con la función de ejemplo y se conectan sus botones (proceso 5).
  6. onStop() llama a enlace.planoSonoro.detener(), así nada sigue sonando al salir de la pantalla.
setContentView(enlace.root)
enlace.root.respetarBarrasDelSistema()
enlace.btnRegresar.setOnClickListener { regresarAAprendizaje() }
enlace.planoSonoro.configurar("f de x igual a 2x más 1", -4.5, 4.5, -10.0, 10.0) { x -> 2 * x + 1 }
enlace.planoSonoro.vincularBotones(enlace.btnSonidoLineal, enlace.btnReferencias)

El primer parámetro es el texto que dice la voz, así que se escribe como se pronuncia ("2x más 1"), no con símbolos.

Botón "Regresar" (Navegacion.kt)

Los 12 diseños de tema tienen un AppCompatButton con id btnRegresar, así que ViewBinding genera enlace.btnRegresar en todos. El texto visible es @string/regresar ("Regresar") y la descripción para TalkBack es @string/regresaraprendizaje ("Regresar a Aprendizaje"). Al tocarlo, regresarAAprendizaje() (una función de extensión de Activity):

  1. Crea un Intent hacia MainActivity con el dato extra EXTRA_SECCION = SECCION_APRENDIZAJE.
  2. Le agrega FLAG_ACTIVITY_CLEAR_TOP, que cierra todas las Activities que estén encima de MainActivity (por ejemplo, plano 1 y plano 2 a la vez), y FLAG_ACTIVITY_SINGLE_TOP, que reutiliza la MainActivity existente.
  3. Llama a startActivity y a finish(). MainActivity recibe el Intent en onNewIntent (proceso 1).
fun Activity.regresarAAprendizaje() {
    val intencion = Intent(this, MainActivity::class.java)
        .putExtra(EXTRA_SECCION, SECCION_APRENDIZAJE)
        .addFlags(Intent.FLAG_ACTIVITY_CLEAR_TOP or Intent.FLAG_ACTIVITY_SINGLE_TOP)
    startActivity(intencion)
    finish()
}

Después de regresar, el botón Atrás del sistema cierra la app desde Aprendizaje, en lugar de volver al tema: las pantallas de tema ya no están en la pila.

Barras del sistema (BarrasSistema.kt)

Desde Android 15, las apps que apuntan a esa versión se dibujan "de borde a borde": la ventana ocupa también el área de la barra de estado y la de navegación. respetarBarrasDelSistema() lo compensa así:

  1. Guarda el padding que la vista ya tenía en el XML (por ejemplo, 16dp en vista_principal).
  2. Registra un ViewCompat.setOnApplyWindowInsetsListener. Android lo llama con los insets: cuánto miden las barras (systemBars()), el recorte de la cámara (displayCutout()) y el teclado en pantalla (ime()).
  3. Aplica setPadding(original + barra) en cada lado; abajo usa la mayor medida entre la barra de navegación y el teclado.

Se aplica a la raíz de cada pantalla: raizPrincipal en MainActivity y enlace.root (el ScrollView) en cada tema. Como el ScrollView recorta su contenido en el padding, el texto desplazado desaparece antes de llegar a la hora.

4. Plano cartesiano en dos partes

ArchivosPlanoCartesianoActivity.kt, PlanoCartesiano2Activity.kt ResultadoNavegación Siguiente / Anterior entre las dos partes, y "Regresar" a Aprendizaje desde cualquiera.
  1. Parte 1: enlace.btnSiguientePlano abre la parte 2 con startActivity(Intent(this, PlanoCartesiano2Activity::class.java)).
  2. Parte 2: enlace.btnAnteriorPlano llama a finish(). Se usa finish() en lugar de otro Intent para no apilar pantallas repetidas: el botón Atrás del sistema y "Anterior" hacen lo mismo.
  3. En las dos partes, enlace.btnRegresar usa regresarAAprendizaje(). Desde la parte 2, CLEAR_TOP cierra las dos partes de una vez.

En el diseño, los botones de cada parte forman una "fila de navegación": un LinearLayout horizontal con baselineAligned="false", 8dp de padding en cada orilla y dos botones con layout_width="0dp" y layout_weight="1" (miden igual), separados por 10dp de margen en cada uno. Parte 1: Regresar | Siguiente. Parte 2: Anterior | Regresar.

5. Configuración del plano sonoro

ArchivoPlanoSonoroView.kt (configurar, vincularBotones) EntradaLa Activity del tema. ResultadoEl plano dibujado, con el resumen precalculado y la descripción para TalkBack.
  1. configurar(descripcion, xMin, xMax, yMin, yMax, f) guarda la función y la ventana del plano (qué parte de los ejes se ve y se escucha).
  2. Calcula una sola vez resumen = DescriptorGrafica.describir(...) (proceso 13).
  3. Asigna contentDescription: "Plano con la gráfica de … Desliza un dedo de izquierda a derecha para explorarla. Toca dos veces para escuchar el recorrido completo."
  4. vincularBotones(reproducir, referencias) conecta los botones. Si algo está sonando, cualquiera de los dos lo detiene; si no, el primero llama a reproducir() y el segundo a escucharReferencias().

Cómo elegir la ventana: debe incluir los puntos importantes (cruces, vértices) y dejar un poco de margen arriba y abajo, porque lo que sale de la ventana se oye como silencio. Ejemplo: la cuadrática x² − 4x + 3 usa x ∈ [−1, 5] e y ∈ [−2, 8] para que se oigan el vértice (2, −1) y los cruces en 1 y 3.

6. Secuencia guiada y turnos

ArchivoPlanoSonoroView.kt EntradaBotón "Reproducir sonido" o doble toque sobre el plano con TalkBack (performClick). ResultadoReferencias (solo la primera vez) → presentación hablada → recorrido sonoro → resumen hablado.
Figura 1. Orden de los pasos del recorrido guiado.

El mecanismo de turnos

Casi todos los pasos son asíncronos (la voz avisa al terminar, los tonos esperan con postDelayed). Si la persona toca "Detener" o empieza a explorar en medio de la secuencia, los pasos pendientes no deben ejecutarse. Para eso:

  1. turno es un entero que crece cada vez que empieza o se cancela una acción (cancelarTodo() hace turno++).
  2. Cada secuencia guarda su número en mi al empezar.
  3. Antes de cada paso se comprueba if (mi != turno) return: si cambió, la secuencia ya no es la vigente y se descarta sola.

ejecutar(mi, pasos, luego)

Recibe una lista de Paso: Paso.Decir(texto) o Paso.Tono(altura). Ejecuta el primero y, cuando termina, se llama a sí misma con el resto. Al vaciarse la lista, ejecuta luego(). Así cualquier guion (referencias, presentación, resumen) se escribe como una lista simple.

ejecutar(mi, listOf(Paso.Decir("Gráfica de $descripcion. De izquierda a derecha."))) {
    iniciarRecorrido(mi)
}

7. Espera por TalkBack

despuesDeTalkBack(mi, accion) pregunta a AccessibilityManager si la exploración táctil está activa (isTouchExplorationEnabled, que es lo que activa TalkBack). Si lo está, espera 1500 ms antes de la acción; si no, solo 100 ms. Además, empezarTurno() cambia el texto del botón a "Detener sonido" antes de esperar, para que TalkBack lo anuncie durante la espera y no encima del sonido.

Ícono del botón: vincularBotones guarda el ícono original del XML (compoundDrawablesRelative[2], el drawableEnd) en iconoReproducir. empezarTurno() pone iconoDetener (ico_detener, ■) con setCompoundDrawablesRelativeWithIntrinsicBounds, y terminar() restaura el texto y el ícono originales (▶). Así el estado se entiende por la palabra y por la forma.

8. Tonos de referencia

  1. secuenciaReferencias(mi, luego) arma la lista: decir "parte más baja" → Tono(0.0) → decir "parte más alta" → Tono(1.0).
  2. Si el eje X está dentro de la ventana (0.0 in yMin..yMax), agrega "altura del eje X" y Tono((0 − yMin) / (yMax − yMin)).
  3. Cada tono dura DURACION_TONO_MS (900 ms), seguido de una pausa de 250 ms.
  4. Al terminar, marca referenciasEscuchadas = true: los siguientes recorridos ya no las repiten. El botón "Escuchar tonos de referencia" las vuelve a tocar cuando se quiera.

9. Síntesis del recorrido

ArchivoSonidoGrafica.kt (reproducir, sintetizarRecorrido) EntradaFunción, ventana y duración (6000 ms). ResultadoUna pista de audio estéreo que se reproduce, más la lista de cruces con los ejes.
  1. lanzar() incrementa version, libera la pista anterior y sintetiza en un hilo de fondo para no congelar la pantalla.
  2. Calcula n = 44100 × 6 muestras. Para cada muestra i:
    • avance = i / (n − 1) (de 0 a 1) y x = xMin + (xMax − xMin) × avance.
    • y = f(x). Es visible si es finita, está dentro de [yMin, yMax] y no saltó más del 2 % del rango desde la muestra anterior (así una asíntota suena como silencio).
    • Si x pasa de negativo a ≥ 0: se programa un tic y se registra EventoEje(avance, EJE_Y).
    • Si y cambia de signo (o llega a 0): se programa un bip y se registra EventoEje(avance, EJE_X).
    • La frecuencia objetivo es frecuenciaParaAltura((y − yMin) / (yMax − yMin)) = 220 × 2^(2·altura) Hz.
    • La frecuencia y la amplitud se acercan a su objetivo con un filtro suave (constante de 4 ms) para evitar clics.
    • La muestra es amplitud × sin(fase), más el tic (1200 Hz, 25 ms) o el bip (1760 Hz, 70 ms) si están activos.
    • El paneo es panoramaParaAvance(avance) = 0.08 + 0.84 × avance. Con potencia constante: izquierda = muestra × cos(balance·π/2), derecha = muestra × sin(balance·π/2).
  3. Aplica un fundido final de 20 ms.
  4. crearPista() construye un AudioTrack en modo STATIC (toda la pista en memoria, sin cortes) y lo reproduce.
  5. Llama a alIniciar(eventos) para que la vista empiece a seguir el progreso.
internal fun frecuenciaParaAltura(altura: Double): Double =
    FRECUENCIA_MINIMA * 2.0.pow(altura.coerceIn(0.0, 1.0) * OCTAVAS_GRAFICA)

reproducirTono(altura, duracionMs) usa el mismo camino con sintetizarTono: un seno fijo al centro, con entrada y salida suaves de 20 ms.

10. Seguimiento: punto y vibración

  1. seguirRecorrido(mi) se ejecuta cada 16 ms con un Handler (no depende de que la pantalla se dibuje, así funciona aunque TalkBack oscurezca la pantalla).
  2. Pide sonido.progreso(), que es playbackHeadPosition / totalMuestras: la posición real del audio, no un cálculo de tiempo.
  3. Para cada EventoEje entre el progreso anterior y el actual, vibra con ejeX() o ejeY().
  4. Guarda progresoActual y llama a invalidate() para redibujar el punto.
  5. Cuando progreso() devuelve null (terminó el audio), dice el resumen y llama a terminar().

11. Exploración con el dedo

ArchivoPlanoSonoroView.kt (onTouchEvent, onHoverEvent, explorar) EntradaDedo sobre el plano. Sin TalkBack llegan eventos touch; con TalkBack, eventos hover. ResultadoUn tono que sigue la altura de la gráfica bajo el dedo; al soltar, la voz dice las coordenadas.
  1. Sin TalkBack: ACTION_DOWN pide al ScrollView que no intercepte el gesto (requestDisallowInterceptTouchEvent(true)), llama a empezarExploracion() y luego a explorar(x). ACTION_MOVE llama a explorar(x). ACTION_UP llama a terminarExploracion(anunciar = true).
  2. Con TalkBack: TalkBack convierte el deslizamiento de un dedo en HOVER_ENTER / MOVE / EXIT. Se llama primero a super.onHoverEvent (para que TalkBack enfoque y lea el plano) y después a la misma lógica.
  3. empezarExploracion() cancela cualquier recorrido en curso e inicia TonoContinuo.
  4. explorar(xPantalla):
    • Convierte el píxel en avance (0 a 1) y luego en x. Solo importa la posición horizontal, así la persona no necesita "atinarle" a la curva.
    • Calcula y = f(x); si es visible, manda la altura a tono.mover(altura, balance); si no, mover(null, …) lo silencia.
    • Si x cambió de signo: tono.marcarEjeY() y vibracion.ejeY(). Si y cambió de signo: marcarEjeX() y ejeX().
  5. terminarExploracion(true) detiene el tono y dice "x igual a 1.5, y igual a 4" (o "En x igual a … la gráfica no existe").

performClick() no se llama desde onTouchEvent a propósito: si se llamara, cada vez que alguien explora y suelta el dedo empezaría el recorrido. El clic solo llega por TalkBack (doble toque) o por teclado o switch, y en esos casos sí inicia el recorrido.

12. Tono continuo en streaming

ArchivoTonoContinuo.kt Lo usanPlanoSonoroView (temas) y CapaSonora (graficadora, proceso 20). Por qué separadoEl recorrido se genera completo antes de sonar; la exploración no sabe adónde irá el dedo, así que genera el audio en bloques pequeños mientras suena.
  1. iniciar() incrementa generacion, vacía objetivoAlturas (silencio) y lanza un hilo con bucle(mi).
  2. La interfaz llama a mover(alturas, balance) con una altura por rama de la curva (de 0 a 1), o a mover(altura?, balance) si solo hay una; null o una lista vacía significan "aquí no hay gráfica". Las alturas se guardan ordenadas de menor a mayor, hasta MAX_VOCES = 4.
  3. El hilo crea un AudioTrack en modo STREAM, con el búfer mínimo y PERFORMANCE_MODE_LOW_LATENCY (Android 8 o superior).
  4. En cada vuelta genera 256 cuadros estéreo (≈ 6 ms), leyendo los objetivos @Volatile que escribe la interfaz (objetivoAlturas, objetivoBalance) y los contadores atómicos de tic y bip.
  5. Cada voz tiene su propia frecuencia, amplitud y fase. Las voces presentes suenan con AMPLITUD_GRAFICA / presentes (el volumen se reparte para no saturar); las que sobran bajan a cero conservando su tono, para apagarse sin salto. Una voz que reaparece entra directo en su tono.
  6. Suaviza la frecuencia (10 ms), la amplitud y el balance (6 ms), suma las voces, agrega tic o bip y escribe el bloque con pista.write, que bloquea hasta que hay espacio. Ese bloqueo marca el ritmo del bucle.
  7. detener() incrementa generacion. El hilo ve que ya no es el vigente, baja la amplitud a cero (sin clic) y libera la pista. Si se inicia otra exploración enseguida, el hilo viejo se apaga solo y no compite con el nuevo.

13. Resumen hablado

ArchivoDescriptorGrafica.kt (describir) EntradaFunción y ventana. ResultadoTexto como "Empieza a la izquierda, por debajo del eje X, y va subiendo. Cruza el eje X en x igual a menos 0.5. …"
  1. Muestrea 801 puntos de izquierda a derecha (pasoX = (xMax − xMin) / 800).
  2. Inicio: en el primer punto donde la función existe, describe la posición respecto al eje X (por debajo, por encima, sobre él, o fuera del plano). Si no existía desde el borde, busca con bisección dónde empieza (borde) y dice "No existe a la izquierda de x igual a 0. Ahí aparece…".
  3. Dirección inicial: agrega "y va subiendo" o "y va bajando".
  4. Sucesos (cada uno con su x, para ordenarlos):
    • Cruce del eje Y: "Cruza el eje Y en y igual a f(0)".
    • Cruce del eje X: el valor exacto se obtiene con biseccion (50 iteraciones). Se ignora el último punto para no repetir lo que dirá "Termina…".
    • Cambio de dirección: con búsqueda ternaria (extremo) se localiza el punto más alto o más bajo y se dice "Llega a su punto más alto en x igual a …, y igual a …, y empieza a bajar".
    • Deja de existir: con borde.
  5. Si cruza ambos ejes en (0, 0), reemplaza los dos sucesos por "Pasa por el origen".
  6. Final: "Termina a la derecha, …".
  7. numero(valor) redondea a 2 decimales, quita ceros sobrantes y cambia "-" por "menos", porque el texto se escucha, no se lee.

La tolerancia (tolerancia = rango × 10⁻⁶) evita que el ruido numérico, como sin(2π) ≈ −2.4 × 10⁻¹⁶, se interprete como un cruce.

14. Voz encadenada (Narrador)

  1. Se crea al conectar la vista (onAttachedToWindow), para que el motor de voz ya esté listo cuando se necesite.
  2. onInit: intenta es-MX y, si falta, es. Registra un UtteranceProgressListener.
  3. decir(texto, luego): genera un id único (sara0, sara1…), guarda luego en un mapa y habla con QUEUE_FLUSH (interrumpe lo anterior).
  4. Cuando el motor avisa onDone(idFrase), saca el callback del mapa y lo ejecuta en el hilo principal.
  5. Si el motor aún se está iniciando, guarda el texto como pendiente. Si no hay motor de voz, ejecuta luego enseguida: la secuencia continúa sin voz y el sonido no se bloquea.
  6. callar() vacía los callbacks y detiene el habla; cerrar() libera el motor.

15. Vibración

Vibracion.kt obtiene el vibrador del sistema (VibratorManager en Android 12 o superior, VIBRATOR_SERVICE antes) y ofrece dos patrones con VibrationEffect.createWaveform:

FunciónPatrón (ms)Significado
ejeX()0, 60Una vibración firme: la gráfica cruza o toca el eje X.
ejeY()0, 20, 70, 20Dos toques cortos: se pasa por x = 0.

Requiere el permiso android.permission.VIBRATE, que ya está en el manifiesto.

16. Dibujo del plano

  1. onDraw(lienzo) dibuja el fondo redondeado (#1C1C1C, radio 16dp) y reduce el marco 10dp por lado.
  2. dibujarCuadricula: líneas cada 1, 2 o 5 unidades según el rango (pasoCuadricula), ejes en #BDBDBD y etiquetas "x" e "y".
  3. Recorta al marco (clipRect) y traza la curva con construirCurva: 400 puntos, cortando el trazo donde la función no existe o salta (asíntotas).
  4. Durante el recorrido, dibuja encima el tramo recorrido en magenta (5dp) y el punto actual (círculo de 8dp con borde blanco). Al explorar, dibuja el punto bajo el dedo y una línea vertical tenue.

Conversión de coordenadas: aPantallaX(x) = marco.left + (x − xMin) / (xMax − xMin) × ancho; en y se invierte, porque en pantalla y crece hacia abajo.

17. Graficadora con GeoGebra

ArchivosControladorGrafica.kt, assets/geogebra.html, vista_grafica.xml EntradaSección Graficar del menú. ResultadoGeoGebra cargado, con un campo, un teclado y botones para graficar y escuchar.
  1. El constructor obtiene las vistas del XML y agrega por código, debajo de los botones, el mensaje de estado (región live que TalkBack lee sola), el teclado y el contenedor de parámetros.
  2. configurarWebView(): habilita JavaScript y almacenamiento, desactiva el oscurecimiento automático, registra Puente como objeto Android en JavaScript y carga https://appassets.androidplatform.net/assets/geogebra.html. Esa dirección no sale a internet: WebViewAssetLoader (librería androidx.webkit) la intercepta en shouldInterceptRequest y responde con los archivos de assets/. Se usa en lugar de file:// porque el WebView bloquea muchas cosas que GeoGebra necesita cuando la página viene de un archivo. Si algo pidiera otra dirección, se anota en el registro como Pedido fuera de la app.
  3. En el HTML, <script src="geogebra/deployggb.js"> carga el instalador local y visor.setHTML5Codebase("geogebra/HTML5/5.0/web3d/", true) le dice que el motor está en la app (true = sin conexión). El idioma se fija en "es", porque solo se incluyeron los textos en español e inglés.
  4. El HTML crea new GGBApplet(opcionesVisor) con "perspective": "G" (solo la vista gráfica: sin el panel de álgebra, que en pantallas verticales tapaba casi toda la gráfica). Al cargar, guarda la API en aplicacionGeogebra, repite setPerspective("G") por seguridad, llama a fijarVentanaInicial() (X de −10 a 10 y Y calculada con la proporción alto ÷ ancho de la página, para que los dos ejes tengan la misma escala y un círculo se vea redondo), registra un oyente de cambios de vista (registerClientListener, evento viewChanged2D) y envía enviar("listo", "").
  5. Al pulsar Graficar: AnalizadorFuncion.analizar(texto) (proceso 18) → capa.borrarMapa() → se crean los controles de parámetros → vistaWeb.evaluateJavascript("graficar(" + plan.aJson(valores) + ")").
  6. En JavaScript, graficar(plan) borra lo anterior, crea los parámetros, crea curvaG (y evaluarG si es implícita), oculta su etiqueta, guarda modoActual, responde enviar("grafica", {ok}) y llama a programarMapa() (proceso 20).
  7. Al mover un parámetro: fijarParametro('a', 1.5) actualiza GeoGebra en vivo y llama a programarMapa(); sin TalkBack, la voz dice el valor 350 ms después de soltar el control.
  8. Si GeoGebra no responde en 15 s, se muestra "GeoGebra no terminó de cargar. Sal de la sección y vuelve a entrar."

Actualizar la versión de GeoGebra

  1. Descargar el paquete "GeoGebra Math Apps Bundle" desde https://download.geogebra.org/package/geogebra-math-apps-bundle y descomprimirlo en una carpeta aparte.
  2. Reemplazar en assets/geogebra/: deployggb.js, HTML5/5.0/web3d y HTML5/5.0/css, y copiar README.txt como LICENCIA_GEOGEBRA.txt.
  3. En HTML5/5.0/web3d/js, borrar los properties_keys_*.js que no sean es o en (ahorra unos 20 MB).
  4. Compilar, abrir la graficadora y revisar en el registro (adb logcat -s SaraWeb) que diga "codebase loaded: 'geogebra/HTML5/5.0/web3d/'" y que no aparezca ningún "Pedido fuera de la app". Probar al final con modo avión y Wi-Fi apagado.

18. Análisis de la función escrita

  1. limpiar(texto): convierte ² ³ π √ − × · ÷ a su forma ASCII, la coma decimal a punto y los corchetes a paréntesis.
  2. expandirLetras → expandir(grupo): separa grupos de letras pegadas: "ax" → "a*x", "senx" → "sin(x)", "pix" → "pi*x". Los candidatos se ordenan del más largo al más corto, para que "arcsen" gane a "sen".
  3. El alias traduce del español a GeoGebra (sen → sin, raiz → sqrt, log → log10).
  4. Si hay "=": decide entre explícita (y = … o f(x) = …) e implícita (cualquier otra ecuación en x e y, como x² + y² = 25). Sin "=": es explícita salvo que aparezca y.
  5. parametros(): toda letra suelta distinta de x, y, z, e, i se vuelve un control deslizante (máximo 6).
  6. Devuelve Analisis.Valido(plan) o Analisis.Invalido(mensaje) con un mensaje que se anuncia en voz alta.

19. Teclado matemático

  1. El campo etFuncion tiene setShowSoftInputOnFocus(false): el teclado del sistema no aparece y se muestra el propio.
  2. Tres pestañas (mostrarPagina): 123, f(x) y abc. Cada página es una lista de filas de Tecla.
  3. Cada Tecla tiene etiqueta (lo que se ve), insertar (lo que se escribe), voz (lo que lee TalkBack), atras (cuántos caracteres retrocede el cursor, por ejemplo 1 para dejarlo dentro de "sqrt()"), tipo (color) y accion.
  4. pulsar(tecla): inserta en la posición del cursor (insertar), borra (borrar; mantener presionado borra todo), mueve el cursor (mover) o acepta y grafica.
  5. Cada pulsación da retroalimentación háptica (KEYBOARD_TAP).

20. Sonificación y exploración en la graficadora

Botón Reproducir

  1. Al pulsar Reproducir: muestrear(modo, cantidad) en JavaScript recorre la ventana visible de GeoGebra con calcularSeries(modo, cantidad, ventana).
  2. Explícita: en cada columna x, toma curvaG(x) si está dentro de la vista.
  3. Implícita: en cada columna, recorre 40 divisiones en y buscando cambios de signo de evaluarG(x, y) e interpola el cruce. Puede haber varias y por columna (por ejemplo, el círculo tiene dos).
  4. Kotlin recibe series y llama a MotorAccesibilidad.reproducirSerie, que normaliza al rango real de la curva y sintetiza hasta 4 voces simultáneas (una por rama), con duración total de unos 5 s.

Explorar con el dedo (CapaSonora.kt)

ArchivosCapaSonora.kt, TonoContinuo.kt, assets/geogebra.html, ControladorGrafica.kt, vista_grafica.xml EntradaDeslizar un dedo sobre la gráfica: con el interruptor "Explorar con el dedo" encendido, o en cualquier momento con TalkBack. ResultadoLas mismas reglas de sonido que en los temas: tono según la altura, paneo según x, tic y bip en los ejes, vibración y coordenadas al soltar.

En los temas, la función vive en Kotlin y se calcula al instante. En la graficadora vive dentro de GeoGebra (JavaScript), y preguntarle en cada movimiento del dedo sería lento y asíncrono. Por eso la página manda un mapa de la zona visible cada vez que algo cambia, y la capa lo consulta localmente.

  1. Diseño. En vista_grafica.xml, un FrameLayout de 350dp contiene el WebView y, encima, la CapaSonora, las dos en match_parent. Como GeoGebra está en perspectiva "G", la gráfica llena el WebView y cada píxel de la capa corresponde al mismo punto de la gráfica.
  2. Programar el mapa. programarMapa() se llama al graficar, al mover un parámetro y cuando GeoGebra avisa viewChanged2D (mover o hacer zoom). Reinicia un temporizador de 250 ms, así muchos cambios seguidos producen un solo mapa.
  3. Calcular el mapa. enviarMapa() obtiene la ventana con vista() (esquinas Corner(1) y Corner(3)), calcula 300 columnas (explícita) o 120 (implícita) con calcularSeries y envía enviar("mapa", {xMin, xMax, yMin, yMax, series}). Escribe en el registro cuánto tardó (SaraWeb: "Mapa de 300 columnas en 40 ms").
  4. Recibir el mapa. ControladorGrafica.procesarMapa convierte el JSON en una lista de DoubleArray y llama a capa.fijarMapa(...), que ordena los valores de cada columna y actualiza la descripción para TalkBack.
  5. Toque sin TalkBack. onTouchEvent devuelve false si exploracionActiva está apagada: el toque pasa al WebView de abajo y GeoGebra mueve o hace zoom. Encendida, pide al ScrollView que no intercepte y explora.
  6. Con TalkBack. onHoverEvent explora siempre. El WebView está marcado IMPORTANT_FOR_ACCESSIBILITY_NO_HIDE_DESCENDANTS, así TalkBack enfoca la capa y no los elementos internos de GeoGebra. Tocar dos veces llama a performClick() → alTocarDosVeces → botón Reproducir.
  7. Explorar. explorar(x) convierte la posición en columna (avance × (columnas − 1)), pasa las alturas de esa columna a tono.mover(alturas, panoramaParaAvance(avance)) y dibuja la línea y un punto por rama.
  8. Cruces. revisarCruces(desde, hasta) revisa todas las columnas entre la anterior y la actual (por si el dedo se movió rápido): tic y doble vibración si cambia el signo de x; bip y vibración si alguna rama cambia de signo en y con un salto menor al 20 % del alto visible (un salto mayor es una asíntota).
  9. Soltar. terminarExploracion detiene el tono y dice las coordenadas con Narrador, de arriba hacia abajo: "x igual a 3, y igual a 4 y menos 4", o "no hay gráfica en la zona visible". Si aún no hay gráfica, dice "Primero grafica una función".
  10. Otros sonidos. Al empezar a explorar, alEmpezar detiene el audio del botón Reproducir (motor.detenerAudio()).

22. Pruebas y compilación

Requisitos: Android Studio (incluye el JDK en jbr). Desde la raíz del proyecto:

gradlew.bat :app:assembleDebug        # genera app/build/outputs/apk/debug/app-debug.apk
gradlew.bat :app:testDebugUnitTest    # corre las pruebas unitarias

DescriptorGraficaTest comprueba el resumen de las 7 funciones de ejemplo: cruces exactos (−0.5, ±1.73, 1, 3), vértices, "Pasa por el origen", el inicio del logaritmo y el formato de números. Si se cambia el algoritmo del resumen, estas pruebas avisan si alguna frase cambió de significado.

Prueba en un teléfono real

  1. En el teléfono: Ajustes → Acerca del teléfono, tocar 7 veces "Número de compilación"; luego, en Opciones de desarrollador, activar Depuración USB.
  2. Conectar por cable y aceptar "¿Permitir depuración USB?".
  3. Comprobar la conexión e instalar: 
    adb devices                          # debe listar el teléfono como "device"
gradlew.bat :app:installDebug        # compila e instala en el teléfono conectado
  4. Para revisar errores mientras se usa la app: adb logcat -b crash. Para ver qué audio está sonando: adb shell dumpsys audio.

En Git Bash, los comandos de adb con rutas del teléfono (/sdcard/...) necesitan MSYS_NO_PATHCONV=1; si no, Git Bash convierte la ruta a una de Windows.

La prueba del 8 de noviembre en un Galaxy con Android 16 está en la sección 14 de la documentación de arquitectura. Las pulsaciones enviadas por adb no pasan por los gestos de TalkBack, así que la exploración con el dedo bajo TalkBack, el paneo y la vibración deben probarse a mano.

23. Receta: agregar un tema nuevo con sonido

  1. Crear res/layout/vista_funcion_nueva.xml copiando uno existente. Debe incluir PlanoSonoroView con id planoSonoro, el botón btnSonidoNueva, btnReferencias y, al final, el botón btnRegresar.
  2. Agregar los textos a strings.xml (nombres en español, sin acentos).
  3. Crear FuncionNuevaActivity.kt: 
    class FuncionNuevaActivity : AppCompatActivity() {
    private lateinit var enlace: VistaFuncionNuevaBinding

    override fun onCreate(estadoGuardado: Bundle?) {
        super.onCreate(estadoGuardado)
        enlace = VistaFuncionNuevaBinding.inflate(layoutInflater)
        setContentView(enlace.root)
        enlace.root.respetarBarrasDelSistema()
        enlace.btnRegresar.setOnClickListener { regresarAAprendizaje() }
        enlace.planoSonoro.configurar("f de x igual a raíz de x", -1.0, 9.0, -1.0, 4.0) { x -> sqrt(x) }
        enlace.planoSonoro.vincularBotones(enlace.btnSonidoNueva, enlace.btnReferencias)
    }

    override fun onStop() {
        super.onStop()
        enlace.planoSonoro.detener()
    }
}
  4. Registrarla en AndroidManifest.xml: <activity android:name=".FuncionNuevaActivity" android:exported="false" />.
  5. Agregar su botón en vista_aprendizaje.xml y su startActivity(Intent(...)) en configurarBotonesAprendizaje.
  6. (Opcional) Agregar una prueba del resumen en DescriptorGraficaTest.
